## 公司发布 / 官方博客

### 1. 蚂蚁数科发布 Agent Factory，ZOLOZ 推出 KYA agent 信任治理（11/03）
蚂蚁数科（Ant Digital Technologies）在 11 月 3 日香港金融科技周上发布“Agent Factory”全场景 AI 解决方案框架，并宣布对其安全平台 ZOLOZ 做重大升级，推出 KYA（Know Your Agent）方案。按通稿口径，Agent Factory 的全栈能力从 AI 平台到区块链基础设施作为一个集成系统运行：Agentar 负责 agent 从开发、部署到规模化管理的过程，ZOLOZ 负责 agent 时代的身份验证与安全风险，LingDT 提供面向复杂行业任务的专用模型能力，区块链与隐私计算技术用于保障安全可信的数据流通与业务协作。蚂蚁数科首席执行官赵闻飙在通稿中把企业 AI 演进描述为三个阶段：企业采用大模型、agent 进入业务流程、agent 进入组织运营，并称当 agent 数量从几个增长到几十个、上百个时，如何规模化生产、运行和管理 agent 成为新挑战。首席技术官严莺在通稿中列出把 AI agent 投入真实生产环境的三项挑战：语义鸿沟、信任缺口与成本超支，对应解法为 DTOntology（把分散业务知识映射为 AI 可读本体）、DTHarness（治理执行）与 DTRouter + LingDT（控制推理成本）。KYA 把 ZOLOZ 已有的 KYC（了解客户）与 KYB（了解企业）验证能力扩展到 agent 场景，提供每个 agent 全生命周期的信任治理，通稿原话为“Agentar builds the agents, and ZOLOZ certifies them”。通稿同时引用 IDC 口径：蚂蚁数科在中国 agent 开发平台私有化部署市场中，非云厂商第一、总体第四，在金融行业大模型平台、agent 应用与服务市场占有 13.3% 的领先份额，上述市场份额数字为通稿引用的第三方口径，未附原始报告链接。

### 2. Salesforce 签署收购 Cresta 的最终协议：语音 agent 接入 Service Cloud（11/03）
Salesforce 在 11 月 3 日宣布已签署收购 Cresta 的最终协议，Cresta 提供 AI 语音 agent、面向人工坐席的实时指导与会话分析技术。按多家 11 月 3 日的报道转述的官方口径，Salesforce 计划把 Cresta 与 Service Cloud 结合，把客户通话内容与已有客户记录、服务流程连接起来；Cresta 在交易完成后仍将支持客户使用的联络中心与电话平台。交易预计在 Salesforce 2028 财年第一季度完成，须满足惯常交割条件并获得所需监管批准。官方公告未披露交易金额；The Information 援引知情人士报道的价格为 27 亿美元，该数字未经 Salesforce 或 Cresta 确认，本期按“报道价”与“官方未披露”分开记录，不把报道价写成官方交易价。Salesforce Agentforce 与 Service Cloud 执行副总裁兼总经理 Kishan Chetan 在报道转述中称，语音是服务最难做对、也对客户最重要的环节。这是监测名单内 Salesforce/Tableau 一线的当日并购条目，收录口径为 agent 与客户数据、服务流程的结合，不是 Data Agent 产品本身的发布。

### 3. Atos 获 ISG Agentic AI Services Leader 评级，ADE 把数据工程拆为专门 agent 职能（11/03）
Atos 在 11 月 3 日宣布，在 2026 年 ISG Provider Lens Agentic AI Services 报告中被评为 agentic AI 开发与部署服务大型象限的全球 Leader，高于其 2025 年的 Market Challenger 位置。报告评估的范围包括编排、系统集成、受控执行、治理与人工监督。通稿列出的 Atos 方法三项强项为：自主数据工程（Autonomous Data Engineer，ADE），把数据工程活动拆解为分析、建模、转换、评估与治理等专门 agent 职能；工作流与系统集成，把 AI 决策与路由、分流、安全、数据与工程工作流连接起来；agent 保障基础，在 agent 生命周期内嵌入安全、访问控制、自主边界、风险管理与性能监控。通稿同时提到 Atos 近期推出的 Genesis Intelligence 套件与 Atos Codex（Center of Operations and Data EXcellence），后者把运营数据与上下文同网络安全控制、AI 推理连接，用于受治理的运营行动，上述内容为通稿口径，未附 ISG 报告原文的评分细节。
- [GlobeNewswire 通稿（11/03，经 Manila Times 转载）](https://www.manilatimes.net/2026/11/03/tmt-newswire/globenewswire/atos-positioned-as-a-leader-in-isg-provider-lens-2026-for-agentic-ai-services/2460443)

### 4. Humanbased 推出自助式 AI 数据市场：agent 开发者与领域专家共同定制任务数据（11/03）
Humanbased 在 11 月 3 日（圣马特奥通稿）推出自助式 AI 数据市场，面向 agent 开发者与领域专家共同创建任务专属数据。平台机制为自助式 Campaigns：团队自行设定贡献者要求、报酬与验收标准，无最低项目承诺，可从一个聚焦任务开始，先评估结果再决定后续投入；任务与评审标准可在上线后随模型演进自行修订。创始人 Yi Zhang 在通稿中的表述为，构建 agent 的人应能塑造 agent 学习所用的数据，专家提供判断，平台提供双方共同创建并随需求调整数据的方式。对领域专家一侧，被接受的工作可获得报酬并积累贡献记录与声誉。平台入口为 humanbased.ai。通稿未披露定价、已接入团队数量与数据规模数字，本期不补写上述数字。
- [Humanbased 通稿（11/03）](https://ohsem.me/2026/11/humanbased-launches-self-service-marketplace-for-ai-teams-and-experts-to-co-create-data/)

### 5. LinearB 发布 Agentic Studio：把交付数据转为管理者与 coding agent 的上下文（11/02 通稿，11/03 报道）
LinearB 在 11 月 2 日（GlobeNewswire 通稿）发布 Agentic Studio，面向所有 LinearB 客户开放，agent skill 库进入早期试用。平台做法是把软件交付全生命周期的数据收集起来并归一化：来自不同 Git 与项目管理系统的源数据进入同一模型，同一工程师在不同工具中的身份被匹配，每一次变更从工单到发布被链接起来。管理者可用自然语言查询并获得指标、制品与看板，coding agent 可获得同一上下文，包括历史事件、代码归属与返工记录。首个进入早期试用的 agent skill 为 effort skill，按业务相关性、复杂度与风险（依据该区域代码质量、近期服务事件与归属历史）匹配 coding agent 在一项变更上应投入的工作量。LinearB 在通稿中引用的 2026 年基准覆盖 250 多家组织的 270 万个 pull request，重度使用 AI 的开发者合并 pull request 数量同比接近翻倍，上述基准数字为公司自述。平台同时通过 Anthropic 的 Model Context Protocol（MCP）对外暴露上下文层，外部 agent 与对话助手可直接查询交付指标；公司称 Agentic Studio 提供基于角色的访问控制，用于设定 agent 可查看数据的边界。

## 论文 / arXiv

### 6. HarnessSQL：8B 模型在 Spider 2.0-SQLite 上达 45.2%，14B 达 54.8%（11/02 报道；论文首投 10/08、修订 10/14）
港科大与微软团队的 HarnessSQL 在 11 月 2 日的 Marsbit 报道中披露了长程交互式 text-to-SQL 训练框架的细节，论文 arXiv:2610.12274 首投于 2026 年 10 月 8 日、10 月 14 日修订为 v3，本期按“11 月 2 日报道、10 月论文”记录，不把论文计为 11 月 3 日首投。方法要点为：把交互式 text-to-SQL 形式化为由执行环境合约（Execution Harness）中介的部分可观察马尔可夫决策过程，构建 79 个复杂数据库沙箱（基于 Spider 2.0-Lite 的 30 个 SQLite 与 Spider 2.0-DBT 的 49 个 DuckDB、无损迁移为 SQLite），用 SQL-First 蓝图合成法先从真实引擎抽取 schema、样本值与外键路径、采样可控难度的可执行 SQL，再反向生成自然语言问题与验证 Oracle；沙箱带只读绑定、单语句约束与 60 秒超时保护。动作合约 DSH-SQL 只有四个动作：sql_list_tables、sql_schema、sql_exec、sql_submit，并内置确定性行截断、循环调用警告与压力触发的上下文压缩三项护栏。训练分两阶段：全轨迹 SFT（教师模型在沙箱内自主探索，筛选经 Oracle 验证的高质量多轮轨迹，平均 11.8K token、16 轮交互、14 次真实执行，计算损失时屏蔽环境观测 token）与执行奖励 RL（DAPO 策略，结果等价且合规得 1 分，错误、超时或结果不匹配得 0 分，不设人工中间奖励）。实验数字（均为论文与报道口径，未经外部独立重跑）：Spider 2.0-SQLite 上，HarnessSQL-8B 为 45.2%（同骨干基线 15.5%，OmniSQL-32B 14.8%、Arctic-Text2SQL-32B 16.3%、多智能体系统 MARS-SQL 12.6%），HarnessSQL-14B 为 54.8%；LiveSQLBench 上 8B 为 24.8%、14B 为 28.5%，32B 基线区间为 7.0%–8.9%；消融显示，直接 RL 仅把 8B 从 15.5% 提升到 20.0%，SFT 后到 30.4%，SFT+RL 到 45.2%，上下文从 8K 扩到 32K 时 Spider 2.0 准确率从 27.4% 提升到 45.2%。
